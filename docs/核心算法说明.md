# 核心算法说明

## 问题与特征

给定小区时间序列中的六维向量 x=[RSRP,SINR,PRB,掉线率,时延,吞吐]，生成正常、覆盖不足、干扰风险、负载拥塞、传输异常五类模型候选，辅以多因素异常和待核实诊断。

## 训练数据

`backend/engine.py` 的synthetic函数按五类高斯分布生成样本并截断至合法范围。训练种子2026，每类400条，总计2000条。评估种子9088，每类160条，总计800条。每类均值和标准差直接定义在PROFILES中。样本由假设生成，不是真实网络采集，标签是生成器类别。训练和测试不同随机种子但共享生成机制，评估不能证明实际泛化能力。

## 随机森林

100棵树，最大深度10，random_state=2026，n_jobs=1。使用predict_proba的最大值作为分类候选概率。概率没有进行校准，不解释成故障真实发生概率。推理不读取CSV标签。该模型是经典分类器，未提出新型机器学习架构。

## 孤立森林

100棵树，只用训练集中的400条正常样本拟合，contamination=0.05，random_state=2026。predict=-1标记分布异常，decision_function负值表示低于异常判定边界。它检测偏离参考分布的样本，不单独确认故障类型。contamination是演示假设，需针对现场正常基线重新设定。

## 证据融合

1. RSRP<-105dBm触发覆盖不足候选。
2. SINR<5dB且RSRP>=-105dBm触发干扰风险候选。
3. PRB>85%触发负载拥塞候选。
4. 时延>100ms且覆盖、干扰、负载阈值均未触发，提示传输异常候选。
5. 掉线率>2%补充体验异常证据。

这些阈值为项目启发式配置，并非3GPP规定的通用故障阈值。多个原因同时触发时显示多因素异常。没有根因阈值但模型异常、分布异常或体验异常时，显示待核实。模型概率<0.65或候选与证据冲突时，标记人工复核。阈值判定正常的记录也可能存在未覆盖问题。

## 知识库与大模型

K01–K05为本项目手工撰写的排查知识条目，说明弱覆盖、干扰、拥塞、回传和证据不足的检查顺序。按触发原因检索，不使用向量数据库，因此不能称为语义检索RAG。大模型通过OpenAI兼容chat/completions接口接收摘要、最多12条按小区及诊断类型轮选的异常样本和知识条目，生成自然语言辅助解释。系统提示要求引用证据、区分候选与确认、禁止编造收益。提示词约束不能保证模型不会出错，必须人工审阅。

## 优化输出

给出天线/覆盖检查、资源协调、负载均衡/扩容或回传核查的建议，以及变更后的复测指标。没有优化收益预测与真实调参执行，不声称吞吐已提升。
