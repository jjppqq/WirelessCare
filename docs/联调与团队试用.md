## 如何取得服务配置

API Key是模型服务平台发给你的程序调用凭证。使用聊天产品的登录账号不自动提供项目所需的API凭证。

可选择阿里云百炼的按量API服务。打开官方文档 https://help.aliyun.com/zh/model-studio/get-api-key/ ，从文档进入API Key控制台 https://bailian.console.aliyun.com/cn-beijing/model/settings/api-key 。登录自己的阿里云账号，按平台提示完成认证、服务开通及计费确认。在华北2（北京）创建Key，归属账号选自己，业务空间可用默认业务空间。先确认可用额度及费用，再调用；本项目不代替用户充值或接受服务协议。

官方获取Key文档当前列出的北京配置：

| 项目 | 配置 |
| --- | --- |
| API Base | https://dashscope.aliyuncs.com/compatible-mode/v1 |
| 模型名 | qwen-plus（需在所选地域可用） |
| API Key | 自己账号创建的实际Key，切勿公开 |

不同地域的Key、接入地址和模型列表不通用。若控制台使用业务空间专属新域名，直接复制该空间官方示例中的base_url。不要把示例里的{WorkspaceId}原样填写。本项目对qwen-plus/qwen-flash显式关闭思考模式，使用非流式接口；其他模型需按供应商文档确认同步调用兼容性。

API Key、银行卡、认证信息不应发到聊天里。可以只告诉协作者平台、地域、模型名和没有密钥的报错。

## 在自己电脑完成真实联调

先按README安装依赖，然后在项目根目录执行：

```bash
python scripts/configure_llm.py
python scripts/check_llm.py
python run.py
```

第一条会询问服务地址、模型名和隐藏输入的Key，生成本地llm_config.json。环境变量WIRELESSCARE_API_BASE、WIRELESSCARE_API_KEY、WIRELESSCARE_MODEL优先于该文件；旧环境变量可能覆盖新设置。Key文件已被git忽略，正式代码打包也会排除它和.env。本地文件仍应保管好，Windows用户不要将项目工作目录同步到公开分享盘。

第二条真的向所选模型服务发送项目自建合成KPI、诊断摘要与最多12条轮选异常样本；不使用真实网络数据。输出联调记录outputs/llm_check.json，包含时间、服务地址、模型、耗时、输入哈希、回答哈希和回答内容，不记录Key。未配置时明确退出，不生成成功证明；网络或服务失败也不会记作通过。

收到真实API响应后，人工检查四项：知识编号是否来自K01–K05；是否捏造了输入中不存在的数值；是否将候选原因误称已确认根因；是否给出排查、复测与变更回退要求。在JSON的manual_review中记录true/false及另附意见；全部复核后才能声称本次联调回答通过。不以一次回答证明生产可靠性。

第三条启动网页，导入演示CSV，分别问“哪些小区要优先排查”“为什么判断为拥塞”“哪些证据还不够”。保存页面截图、导出的报告及联调记录。真实数据对外发送前另行取得授权、脱敏；本次试用只用合成数据。

## 约15分钟的团队试用

每位实际操作成员填写团队试用记录.csv，每行一项任务。团队内部保留真实成员与代号对应关系；对外材料不得包含学校名称、校徽或指导老师身份。

1. 按README安装启动，记录操作系统、Python版本及是否成功。
2. 导入demo_data/demo_kpi.csv，确认120条；查看CELL-2覆盖不足、CELL-3干扰风险、CELL-4拥塞、CELL-5传输异常的证据，记录是否理解候选与确诊区别。
3. 在另存的CSV中删掉sinr_db列，确认页面明确拒绝；不能覆盖原示例。
4. 导出Markdown及JSON，确认样本量、输入哈希、知识编号与网页一致。
5. 完成上述真实大模型问答和人工复核；未配置者写“未执行”，不能填通过。
6. 记录遇到的问题、改进建议、截图路径及代码修正后的复测情况。每名成员解释一个自己实际读过的模块，并确认成果使用和AI辅助披露。
